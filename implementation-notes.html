Implementation Notes

Initial interpretation

This migration treats visualize/templates/*/template.md as the only live template authoring contract. Existing template-skill.md content is folded into markdown contracts through a scripted first pass, then old live HTML/template-skill files are removed.

Design decisions

  • Pattern recipes are creation guidance only; they carry minimal examples and no review rubric language.
  • Preview tooling is switched from template previews to explicit fixture previews using visualize/fixtures/manifest.json.
  • Legacy component CSS is not preserved as a component API. Any reusable fixture styling lands under preview-kit/fixture-styles/.

Deviations and tradeoffs

  • The first-pass template contracts preserve each old template's unique failure-mode guidance, but repeated Structure, Creation guidance, and Mobile contract language is intentionally compact and uniform. This keeps the all-at-once migration tractable while preserving the filesystem invariant the spec prioritizes.
  • The legacy placeholder name __COMPONENTS_PLACEHOLDER__ remains in preview templates for compatibility, but it now injects preview-only fixture styles from preview-kit/fixture-styles/. This avoids a mass rename across 100+ design-system preview-template files while still deleting the component-library authoring model.
  • The README template showcase now renders targeted fixture previews because live templates no longer have HTML examples.
