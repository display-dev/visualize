Checkout mechanics

Reserve first, capture second

A checkout does not prove inventory exists and then hope it remains. It temporarily claims the stock before money changes hands.

Mechanism

The hold closes a race window

Availability is only a snapshot. If two buyers see the last unit at the same time, a read alone lets both continue. The reservation turns that snapshot into an exclusive, time-bounded claim.

Grounded example: one unit, two requests

Request A reserves the unit first. Request B then reads zero sellable units and stops before payment capture. If A's payment fails, its reservation expires and the unit becomes sellable again.

  1. 1
    Checkout asks inventory to reserve

    The operation succeeds only if the requested units are still sellable.

  2. 2
    Inventory returns a reservation ID

    The ID ties a bounded claim to this checkout attempt.

  3. 3
    Checkout captures payment

    A successful capture converts the temporary claim into the order's committed allocation.

Deeper model

A reservation is not an order

The hold protects one invariant, but it does not mean checkout is complete. Payment can still fail, the customer can abandon the flow, or the reservation can expire. The system needs a release path because scarcity without expiry would strand inventory.

Do not confuse

  • Available with guaranteed.
  • Reserved with purchased.
  • Payment authorized with inventory committed.
Retain this

One compact model

Read shows possibility. Reservation creates exclusivity. Capture commits value.
