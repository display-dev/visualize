# Heuristics scoring

Concrete artifact heuristics for `review`'s Layer 2. Each heuristic has a name, what it checks, concrete PASS / WARN / FAIL signals, and a severity slot. Apply every heuristic to every artifact; report the per-heuristic verdict; aggregate to the run-summary grade.

Resolved context overrides — if the context declares a register that legitimately violates a heuristic (a brutalist register intentionally fails "scannability"; an editorial register intentionally fails "visibility of the claim" in favor of a slow reveal), demote the finding to *Context-suppressed* per `review.md`'s Override grid. The heuristics below are the fallback when the resolved context is silent.

**Carve-outs from context suppression**: H8 (reader-respect) and H10 (honesty) are NEVER context-suppressible. Any Absolute ban from SKILL.md surfaced under H8 is non-negotiable regardless of context declaration — same model as the detector's `fossil/*` and `slop/generic-gradient` rules (per review.md Override grid). Context cannot whitelist sycophant footers, imperative tricolons, or 3D-on-data-marks by declaring them as identity.

**Heuristic notes must cite their evidence.** Every PASS / WARN / FAIL verdict must reference concrete evidence: a screenshot path or viewport for visual/rendered heuristics, a category label from review.md Layer 2, a detector ruleId, or a specific element + line. "H8 FAIL because sycophant footer" without naming the footer text is unauditable; "H8 FAIL · `<footer>` line 187 — `I hope you find this useful! — Generated by AI`" carries the evidence. A generic PASS such as "looks good" is not a review.

## H1 — Visual primacy of the central element

A single element wins the visual hierarchy — the eye lands on it first. The element doesn't have to be the *claim* (that's H4's job); it has to be the *focal point*, whatever it is (a chart, a quote, a metric, a diagram, a headline).

- **PASS** · one element clearly dominates the visual hierarchy; supporting elements visibly demote.
- **WARN** · two elements tie for visual primacy (e.g. headline competes with a hero metric at similar weight).
- **FAIL** · three or more elements compete for primacy, OR no element rises above the chrome — the eye doesn't know where to land.
- Severity: WARN → info; FAIL → warn.

## H2 — Match with topic register

The two-altitude AI slop test (SKILL.md), restated as a heuristic.

- **PASS** · neither altitude returns "I could guess the template-plus-aesthetic from the topic alone."
- **WARN** · first-order avoided, second-order hits (e.g. fintech-not-navy-and-gold → still terminal-native-dark; AI-tool-not-purple → still editorial-Tufte clone).
- **FAIL** · first-order hits (postmortem-as-red-banner, AI-essay-as-purple-gradient, ML-paper-as-academic-two-column).
- Severity: WARN → warn; FAIL → error.

## H3 — Scannable navigation chrome

The artifact's structural navigation — headings, TOC, labels, anchor points — lets a 30-second skim reveal *what's in it and how it's organized*. Independent of whether the central claim itself is visible (that's H1) and independent of whether the content arrives in the right order (that's H4). H3 is about the navigability of the chrome.

- **PASS** · h2/h3 hierarchy descends visually; TOC (if present) maps to section anchors; labeled metadata gives context without reading body prose; the artifact's structure is legible from the chrome alone.
- **WARN** · structure is present but uneven (h2s have varying visual weight; one section lacks a heading; TOC is missing a top-level entry; header metadata is present but hidden inside unlabeled chips; mobile header/TOC boundary shows doubled separator rules; mobile TOC links wrap like scattered words; a table caption/intro uses lede scale instead of caption scale).
- **FAIL** · no structural chrome — section breaks invisible, no headings or all-the-same-weight headings, no labels on data displays, or data tables have no readable caption/header/body hierarchy. Reader must read body prose to navigate. Apply F-pattern / Z-pattern / grid-scanning principles from [cognitive-load.md](cognitive-load.md) — the artifact's scan path should match its template shape.
- Severity: WARN → info; FAIL → warn.

## H4 — Narrative sequencing (information arrival order)

Content arrives in the order the reader needs it. *What* gets said when. Distinct from H1 (whether the focal element is visually dominant) and H3 (whether the chrome lets the reader navigate). Decisions before justifications. Numbers before adjectives. Claim before context.

- **PASS** · the order matches the template shape (claim → evidence → caveats → methodology for analytical; headline → context → outcome → next-step for announcements; symptom → diagnosis → action for runbooks). See [cognitive-load.md](cognitive-load.md) Information arrival order section.
- **WARN** · order is roughly right but one section is misplaced (methodology before evidence; caveats before claim).
- **FAIL** · the artifact builds up to the claim instead of leading with it ("Here's our background, here's our process, here's what we found" — academic-paper shape on a non-academic register).
- Severity: WARN → info; FAIL → warn.

## H5 — Cite the number, not the adjective

Quantitative claims are quantified. "Much faster" loses to "1.2s vs 3.6s." Adjective stacks ("seamless, robust, holistic") lose to a single specific claim.

- **PASS** · every "faster / better / scalable / robust" claim carries a number, baseline, and comparison.
- **WARN** · most claims are quantified; 1–2 adjective-only.
- **FAIL** · the artifact leans on adjectives where numbers would be tighter (3+ unquantified comparative claims).
- Severity: WARN → info; FAIL → warn.

## H6 — Register coherence

Typography / spacing / color / motion stay register-consistent across the artifact. Not theatrical density in section 1 and compact in section 5. Not editorial serif in the body and mono in the captions for no reason. Tables keep their own internal role hierarchy: caption/header/body/value text should not borrow hero or lede scale.

- **PASS** · the artifact reads as one register end-to-end; differences are deliberate (a dashboard inside a report is allowed to switch density).
- **WARN** · register drifts in one section (e.g. a tutorial that shifts from compact to comfortable mid-document, or a table mixes lede-sized captions with compact cells).
- **FAIL** · multiple registers compete (one section editorial, one section dev-tool, one section presentation) with no anchor.
- Severity: WARN → info; FAIL → warn.

## H7 — Brand-trueness

The artifact reads as the brand's, not as a generic template of its type. A reader who knows the brand should recognize it; a reader who doesn't should at least not mistake it for the modal SaaS / dev-tool / editorial template.

- **PASS** · brand voice + visual identity present at every touchpoint (palette, type, copy register, spacing rhythm).
- **WARN** · brand identity present in some sections, missing in others (e.g. brand-true hero, generic body).
- **FAIL** · the artifact could be from any brand of its type — no `DESIGN.md` fingerprint visible.
- Severity: WARN → warn; FAIL → error.

## H8 — Reader-respect

No sycophant footers, AI attribution, "in conclusion" wrappers, "It is worth noting that…" hedging, em-dash overuse, imperative tricolons. Every Absolute ban in SKILL.md applies; this heuristic covers the cross-cutting copy-side bans.

- **PASS** · prose is unhedged, claims are direct, no meta-prose contaminates the artifact.
- **WARN** · 1 hedging wrapper or 1 sycophant phrase survived.
- **FAIL** · multiple disrespect markers (sycophant footer + "In conclusion" + em-dash overuse + imperative tricolon).
- Severity: WARN → warn; FAIL → error.

## H9 — Rendered-state realism

The artifact handles realistic content and real reading states, not just the demo case. Long names, empty states, missing fields, mobile viewport, dark mode, print preview. Consult [responsive-design.md](responsive-design.md) for the viewport / dark-mode / print expectations.

- **PASS** · edge cases either render correctly or have a designed fallback; the first two phone screens feel intentionally composed, not just non-overflowing.
- **WARN** · one category of edge case fails (e.g. mobile is broken but everything else holds), OR the mobile layout technically works but is visibly less polished than the desktop layout, including rounded metadata chips that wrap as noise, doubled separators that appear only after stacking, or a TOC that becomes a loose word cluster.
- **FAIL** · multiple edge cases fail (mobile + dark mode + long names all break).
- Severity: WARN → warn; FAIL → error.

## H10 — Honesty

Charts encode proportions truthfully (see [data-viz.md](data-viz.md) for the full ruleset). Copy doesn't mislead — no truncated y-axes without callouts, no dual-axis correlation traps, no adjective claims masking weak data, no cherry-picked time windows. Honesty issues that data-viz flags as lie-factor (truncated axis without visible break callout, 3D on data marks, area encoding linear data) are FAIL, not WARN.

- **PASS** · every data display passes the data-viz honesty rules; copy claims match the data.
- **WARN** · one minor honesty issue (an unqualified comparative claim; a label that could be more specific).
- **FAIL** · any data-viz lie-factor violation (truncated axis without callout, 3D on data marks, area for linear data, dual-axis correlation trap), OR any data-vs-copy contradiction.
- Severity: WARN → warn; FAIL → error (ship-blocker).

## Aggregate grading (severity-weighted)

The grade follows severity, not raw FAIL count. A WARN→info is lighter than a WARN→warn; a FAIL→warn is lighter than a FAIL→error.

| Grade | Condition |
|---|---|
| **A** | All PASS, OR 1–2 WARN→info verdicts; no warn-severity or error-severity findings |
| **B** | Any mix that produces ≤2 warn-severity findings, no error-severity findings |
| **C** | 3+ warn-severity findings, OR exactly one error-severity finding from H2 / H7 / H9 |
| **D** | 2 error-severity findings, OR any H8 / H10 FAIL (ship-blocker grade floor) |
| **F** | 3+ error-severity findings |

Verdict → ship/iterate/ship-blocked mapping for review's top line:
- Grade A → **ship**
- Grade B → **ship** with recommendations
- Grade C → **iterate** (see worst-heuristic routing below)
- Grade D / F → **ship-blocked** until error-severity findings are resolved

H8 (reader-respect) and H10 (honesty) FAILs are ship-blockers regardless of grade. They render in `Errors (ship-blockers)` AND in the heuristic table — same finding, two places, with the heuristic note citing the Errors entry by label.

## Routing the next action

Apply SKILL.md's Design judgment first. This table selects a remedy once the reader's task and applicable constraints are understood. Recommendations are not authorization to execute them.

| Worst heuristic | Root cause | Recommended next action |
|---|---|---|
| H1 (visual primacy), H4 (narrative sequencing) | Primary reading path or structural direction remains unresolved | `/visualize explore artifact` to compare arrangements under one brief, within its supported scope |
| H1 (visual primacy) | No element is amplified — everything reads at middle weight | `/visualize bolder` (amplify one focal element) |
| H1 | Too many elements competing (3+ at same weight) | `/visualize simplify` (cut the competing chrome) OR `/visualize quieter` (demote the supporting elements) |
| H3 (scannable chrome) | Necessary headings, labels, or navigation are missing | direct edit to add the structure required by the reader's task; do not assume a TOC is necessary |
| H3 | Chrome is present but visually flat (all h2s same weight) | `/visualize polish` (typography dimension raises hierarchy) |
| H3 | Static header metadata appears as unlabeled rounded chips | `/visualize polish` (replace chips with crisp key-value labels) |
| H3 | Header and mobile contents/TOC create adjacent horizontal rules | `/visualize polish` (collapse to one separator at the mobile breakpoint) |
| H3 | Mobile TOC wraps as unrelated words | `/visualize polish` (turn TOC into a structured list or grid) |
| H3 | Table caption/intro/body roles are visually confused | `/visualize polish` (typography dimension restores table type hierarchy) |
| H4 (narrative sequencing) | Sections are in the wrong order and the intended order is established | direct edit to restore that order |
| H4 | Buildup-to-claim prose ("background → process → finding") | `/visualize simplify` (cuts the buildup, lifts the claim) |
| H2 (topic register), H7 (brand-trueness) | Visual treatment is generic | `/visualize bolder` when the structure works and expression is weak; otherwise apply shared Design judgment |
| H6 (register coherence) | One section is louder than the rest | `/visualize quieter` on the loud section |
| H6 | One section is quieter than the rest | `/visualize bolder` on the quiet section |
| H5 (cite the number), H8 (reader-respect) | Copy-side | direct edit; no verb covers prose-by-prose |
| H9 (rendered-state realism) | Mobile / dark mode / print broken | `/visualize polish` (walks edge-data + final verification) |
| H9 | Mobile technically reflows but feels over-designed or less polished than a simple document | `/visualize polish` (mobile micro-details + medium verification) |
| H9 | Empty states missing / long-name overflow / undefined-field render | direct edit (these are content-state gaps, see polish's "medium / state / semantic gap" root-cause bucket) |
| H10 (honesty) | Any lie-factor violation | direct fix — ship-blocker |
| Any heuristic FAIL AND ≥3 Absolute bans present | Ban-heavy artifact regardless | `/visualize simplify` first (per SKILL.md refuse-and-route), then re-evaluate |

## Output shape inside review.md's report

Render the heuristic verdicts as a section between "Info / aggregate patterns" and "Context-suppressed" in review.md's mandatory output shape:

```
## Heuristic scoring

| # | Heuristic | Verdict | Note |
|---|---|---|---|
| H1 | Visibility of the claim | PASS | central claim lands first |
| H2 | Match with topic register | WARN | second-order: editorial-Tufte echo on a dev-tool topic |
| H3 | Scannability | PASS | TL;DR + headings extract in 30s |
| … | … | … | … |

**Grade: B** (2 WARNs, no FAILs). Worst: H2. Recommended next action: `/visualize bolder` to strengthen the brand's expression within the established structure.
```

Every note must be 1 sentence and must name the evidence that triggered the verdict. PASS notes are mandatory; they should cite the screenshot/viewport, detector result, or element that proves the heuristic holds.
