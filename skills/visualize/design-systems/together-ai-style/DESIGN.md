# Together AI Style

_Independent reference inspired by Together AI's public product and documentation surfaces. Not affiliated with or endorsed by Together AI._

## §1 Canonical Canvas

Together AI style is AI infrastructure with a research edge: serverless inference, fine-tuning, dedicated endpoints, GPU clusters, instant clusters, model catalogues, OpenAI-compatible APIs, batch jobs, and pricing by tokens or hardware. The brand rhythm alternates near-black technical hero bands with white product and pricing surfaces, held together by one distinctive gradient ribbon.

Use dense model tables, code snippets, hardware rows, benchmark tiles, pricing units, endpoint statuses, and cluster reservation flows. Keep the voice direct and performance-oriented. The visual system should feel like the AI cloud underneath other AI products, not like the chat app on top.

### global-header

Use a compact AI-infra nav: Products, Research, Pricing, Docs, Blog, Customers, Contact Sales, Sign in, and Start building. Menus expose Inference, Fine-tuning, Training, GPU Clusters, Dedicated Endpoints, Models, Image, Audio, Code, and Agents.

### ai-acceleration-hero

Hero copy should frame Together as the cloud to train, fine-tune, and run open-source AI models. Pair the headline with a dark canvas, model/API composition, and a gradient ribbon or mesh as the only decorative mark.

### gradient-ribbon

The orange-magenta-periwinkle ribbon is the brand chrome. Use it as a hero stripe, model-flow accent, or divider. Do not turn every card into a gradient or use gradient text.

### inference-api-card

Inference cards show endpoint, model, latency, throughput, input/output token price, request status, and OpenAI-compatible code. The UI should be terse and benchmark-ready.

### model-catalogue-table

Model catalogues are dense: model name, provider, modality, context length, input price, output price, speed, and best use. Rows should support filters for chat, coding, vision, audio, image, embedding, and rerank.

### openai-compatible-code

Code cards show a small OpenAI-compatible client snippet with base URL, model name, messages, streaming, and response. Use copy controls and mono labels.

### serverless-endpoint-card

Serverless endpoint cards emphasize fast start, pay-per-token pricing, model selection, streaming, batching, and autoscale. Use a health badge and recent request rows.

### dedicated-endpoint-card

Dedicated endpoint cards show GPU, replicas, quantization, batch jobs, min/max scale, private model, and reserved throughput. This is for serious production workloads.

### fine-tuning-job-card

Fine-tuning cards show base model, dataset, method, epochs, training tokens, eval result, deployment target, and price. Include status steps: uploading, validating, training, evaluating, deploying.

### gpu-cluster-card

GPU cluster cards show B200, H200, H100, A100, node count, InfiniBand, storage, reservation duration, region, and extend duration action. Use hardware facts, not cloud fluff.

### instant-cluster-flow

Instant cluster flows show choose hardware, attach storage, reserve, SSH or API access, monitor jobs, and extend. Keep it operational and deterministic.

### training-run-panel

Training panels show loss curve, tokens/sec, GPU utilization, checkpoint, job logs, and distributed run status. Use technical graphs, not decorative metrics.

### batch-job-panel

Batch panels show JSONL upload, request count, progress, successful rows, failed rows, output file, and cost. Batch is cost and throughput work.

### benchmark-card

Benchmark cards compare latency, tokens/sec, cost per million tokens, and throughput against baseline runtimes. Use named models and hardware.

### kernel-collection-card

Together Kernel Collection or performance-engine cards should show fused kernels, inference stack, serving optimization, and practical speed gains. Make research visible as infrastructure.

### image-model-card

Image cards show generation model, prompt, dimensions, style controls, safety state, and output grid. Keep it secondary to inference infrastructure but support multimodal breadth.

### audio-model-card

Audio cards show speech model, transcription, TTS, language, duration, and file status. Use waveform sparingly and label exact model names.

### agent-runtime-card

Agent cards should be infrastructure-oriented: tool calls, code execution, model routing, endpoint latency, and guardrails. Avoid consumer chat styling.

### playground-panel

Playground panels show model selector, parameters, prompt, streaming response, token count, and export-to-code action. This is a developer console.

### api-key-card

API key cards show project, environment, key prefix, last used, scope, and revoke action. Keep secret handling clear.

### billing-meter-card

Billing meters show input tokens, output tokens, image/audio units, fine-tuning tokens, GPU hours, storage, and batch discounts. Use exact units.

### pricing-table

Pricing tables are product-critical. Show model rows and per-1M token prices, hardware rates, fine-tuning rates, batch discounts, and dedicated endpoint details. Keep tables scannable and current-source-oriented.

### quota-limit-card

Quota cards show rate limits, concurrent requests, monthly usage, spend cap, and upgrade/contact action. Use clear limit language.

### docs-quickstart

Docs quickstarts use left nav, versioned examples, terminal commands, SDK tabs, and response examples. Keep copy terse.

### customer-proof-card

Customer proof should focus on workloads: inference at scale, cost reduction, fine-tuning, research deployment, and model serving. Avoid generic logo walls without technical proof.

### research-paper-card

Research cards show paper title, model/system, result, code link, and deployment implication. Together's research posture should feel connected to cloud performance.

#### status-incident-card

Status cards show API, inference, dedicated endpoints, clusters, billing, region, and incident updates. Production infra needs state clarity.

### enterprise-security-card

Enterprise cards show private deployments, compliance, data controls, support, SLAs, VPC or networking, and reserved clusters. Keep security concrete.

#### footer-wordmark-band

End with a large, low-contrast Together wordmark or footer band plus product/docs/company/resource links. The sign-off can be oversized but restrained.

## §2 Palette

Together AI's palette is near-black, white, neutral table chrome, and one warm-to-cool gradient. The gradient is not a general palette; it is the brand's single expressive device.

#### deep-navy

Use near-black navy for hero, research, terminal, and dark product bands. It should feel technical, not pure black.

#### white-technical

Use white for model tables, docs, pricing, and dense product grids. High density needs light surfaces.

#### gradient-stops

Use orange, magenta, and periwinkle only as the ribbon or small data accents. Do not apply the full stack to text.

#### mint-surface

Mint can be used as a low-intensity stat or success background. Keep it rare and pale.

## §3 Typography

Typography combines a modern geometric display sans with mono uppercase labels.

#### display-type

Use a geometric sans for headlines and product copy. It should feel poured and technical, with tight tracking and medium weight.

#### mono-labels

Use uppercase mono labels for section eyebrows, table headers, pricing units, endpoint states, and button labels.

#### code-type

Use real monospace for API snippets, JSON, CLI commands, and logs. The code should be copyable and plausible.

## §4 Composition Rules

Together compositions should make AI infrastructure legible as a pipeline: model to endpoint to tokens to hardware to cost.

### pipeline-not-chat

Show endpoints, models, clusters, jobs, and code before chat bubbles. Together powers chat; it is not primarily the chat surface.

### table-as-product

Dense tables are allowed and often necessary. Make them beautiful with alignment, spacing, and strong labels rather than hiding detail.

### gradient-with-restraint

Use one gradient gesture per major view. Overuse makes the system generic AI.

### cost-and-performance-together

Pair throughput and latency with cost units. AI infrastructure buyers need both.

### hardware-visible

Show GPU family, node count, storage, networking, and region when discussing clusters or training.

## §5 Accessibility And States

Technical density requires strong contrast and precise states across dark and light surfaces.

### focus-state

Focus states use white on navy or black on white, with a thin periwinkle or orange outer hint only when contrast survives.

### endpoint-state

Endpoint states use labels: healthy, deploying, scaling, throttled, failed, paused. Pair color with text.

### job-state

Training and fine-tuning jobs need explicit states, progress, logs, and recoverable errors.

### pricing-state

Pricing rows must preserve units and model names. Do not truncate key cost information.

## §6 Anti-Patterns

Together style fails when it looks like a generic AI chatbot startup.

### avoid-gradient-text

Never apply the brand gradient to headings or metrics. Use the ribbon instead.

### avoid-empty-ai-orbs

No abstract glowing spheres or neural-network wallpaper without product context.

### avoid-consumer-chat

Chat messages can appear inside playgrounds, but the brand surface should show infrastructure around them.

### avoid-vague-performance

Do not say "blazing fast" without latency, throughput, model, hardware, or cost context.
