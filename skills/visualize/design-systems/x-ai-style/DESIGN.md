# xAI Style

_Independent reference inspired by xAI's public product, API, and documentation surfaces. Not affiliated with or endorsed by xAI._

## §1 Canonical Canvas

xAI style is a dark, sparse, developer-first frontier AI platform. The current public story is not only a lab homepage: it is Grok, Grok Build, Imagine, Voice, Grokipedia, Grok on X, API Console, docs, pricing, enterprise support, cloud availability, tools, file workflows, and trust/legal infrastructure.

Use a near-black canvas, white typography, thin borders, monochrome pill actions, code blocks, model cards, pricing tables, product links, and restrained illustrative accents for modalities. The brand should feel like an engineering surface for building with models, not a colorful AI assistant landing page.

### global-navigation

Navigation groups Products, Solutions, Developer, Company, Pricing, News, Contact Sales, and Try for free. Product menus include Grok, Business, Government, apps, Grok on X, API Console, Documentation, and CLI.

### frontier-hero

Hero sections should state frontier AI models for what users build. Pair the headline with code, prompt examples, product tiles, or live model surfaces rather than abstract neural graphics.

### unified-api-panel

Unified API panels show text, code, voice, images, and video through one API. Include get API key and read docs actions.

### code-example-card

Code cards should show real SDK examples with environment variables, model names, imports, prompt, request, and output. Keep copyable code central.

### grok-chat-card

Grok chat cards show prompt, response, conversation state, search enabled state, and product path to grok.com or mobile apps.

### grok-build-card

Grok Build cards show a coding task, files read, search results, plan, terminal-like progress, edits, tests, and running state.

### imagine-card

Imagine cards show image and video generation, editing modes, prompt, reference image, resolution, output cost, and quality mode.

### voice-agent-card

Voice cards show real-time conversation, speech-to-text, text-to-speech, voice selection, latency, session cost, and playback controls.

### model-card

Model cards show name, new or stable badge, description, modality, context window, input price, output price, reasoning mode, and tool support.

### pricing-table

Pricing tables should compare text models, coding models, image models, video models, and voice modes. Keep units visible: per token, image, second, minute, hour, or character.

### cost-calculator

Cost calculators show model selector, token inputs, media inputs, output tokens, sliders, reset, and computed cost.

### quickstart-flow

Quickstarts show create account, load credits, generate API key, install SDK, make request, and next steps. Treat setup as a product surface.

### sdk-tabs

SDK tabs include Python, JavaScript, OpenAI-compatible Python, OpenAI-compatible JavaScript, and cURL. Make migration paths obvious.

### docs-sidebar

Docs sidebars show Overview, API and SDK, Console, Grok App, Models, Pricing, API Reference, changelog, streaming, files, tools, migration, community, and FAQ.

### tools-panel

Tools panels show function calling, web search, X search, code execution, collections search, remote MCP tools, and structured outputs.

### files-collections-card

Files and collections cards show upload, file list, metadata, collection search, RAG, citations, and API management.

### batch-async-card

Batch and async cards show job id, queued/running/completed state, deferred completions, result retrieval, and error handling.

### websocket-card

WebSocket cards show session connection, streaming events, realtime voice, partial transcripts, and disconnect handling.

### enterprise-support-card

Enterprise cards show contact sales, custom rate limits, onboarding, monthly invoices, SSO, audit logging, and data residency.

### cloud-availability-strip

Cloud strips show preferred-cloud options such as Azure AI Foundry, OCI Generative AI, and Vertex Model Garden when the surface is about deployment.

### news-release-card

News cards show date, product, release title, and read action. Current news cadence includes integrations, Grok Build, and model updates.

### trust-footer

Trust footers include safety, security, privacy portal, subprocessors, help center, terms, enterprise terms, privacy, cookies, AUP, and brand links.

### status-link

Status links should be visible near developer resources. Reliability is part of the API product.

### social-community-links

Community links include xAI and Grok social accounts plus Discord when appropriate. Keep them secondary.

## §2 Palette

xAI color is primarily dark canvas plus white. Accent color is illustrative and rare.

#### near-black-canvas

Use near-black as the default page floor. Avoid tinted full-page gradients.

#### white-interface

Use white for headings, outline pills, primary filled pills, code text, and model table emphasis.

#### graphite-surface

Use slightly lifted graphite for cards, code blocks, docs panels, and calculator containers.

#### muted-gray

Use cool muted gray for secondary text, metadata, labels, and inactive controls.

#### restrained-modality-accents

Use sunset, violet, blue, or similar accents only inside modality illustrations, model labels, or product tiles. They should not become the page theme.

## §3 Typography

xAI typography is spare and geometric.

#### geometric-display

Use a clean geometric sans for display, regular or medium weight. Let size and space create authority.

#### mono-technical-labels

Use monospace for API keys, endpoints, code snippets, model ids, environment variables, and pricing units.

#### plain-docs-body

Docs body text should be straightforward, readable, and compact enough for technical scanning.

#### terse-buttons

Buttons use short labels: Get API Access, View Documentation, Start building, Contact Sales, Try for free.

## §4 Composition Rules

xAI layouts should feel like a production developer surface.

### product-over-vibe

Show models, API, code, docs, pricing, and tools before atmospheric brand imagery.

### one-api-story

Tie every modality back to the unified API. Do not split text, voice, image, and video into unrelated campaigns.

### code-as-proof

Use code snippets as primary proof. A model platform earns trust by showing the request path.

### table-driven-pricing

Pricing belongs in structured rows. Keep model name, capability, context, and cost aligned.

### dark-only-canonical

Treat the dark canvas as canonical. Light previews can exist for tooling, but the brand system should stay dark-led.

### enterprise-without-bloat

Enterprise content should stay terse: SSO, audit logging, data residency, rate limits, onboarding, invoices.

## §5 Accessibility And States

Dark developer surfaces need precise state contrast.

### focus-state

Use clear white or high-contrast focus rings with enough offset from pill borders and code panels.

### api-key-state

API key states include created, copied, hidden, revoked, expired, insufficient credits, and rate limited.

### model-state

Model states include new, stable, preview, deprecated, retired, playground coming soon, and alias latest.

### request-state

Request states include queued, streaming, tool calling, reasoning, completed, failed, timed out, and retried.

### billing-state

Billing states include credits loaded, usage based, invoice, limit reached, cost estimate, and overage warning.

## §6 Anti-Patterns

xAI style fails when it becomes generic AI glowware.

### avoid-neon-ai-clouds

Do not use glowing blobs, rainbow gradients, or synthetic brain imagery.

### avoid-chatbot-only-framing

Grok is a product, but xAI's developer surface is a platform with API, tools, pricing, and docs.

### avoid-hidden-pricing

Model costs, context, modality units, and enterprise support paths should stay visible.

### avoid-overfriendly-copy

Keep copy direct and technical. Avoid cute assistant language unless reproducing a Grok-specific consumer context.
